# 20260926-1130-snapshot-20260926 Move the lock to snapshot 20260926T000000Z

- **status**: implementing
- **createdAt**: 2026-09-26 11:30
- **approvedAt**: 2026-09-26 11:12
- **relatedTask**: 20260926-1040-runtime-lock-security

## Context

Scanned 2026-09-26: every Debian package pinned in `locks/upstream.lock` (339 rows, 173 names,
amd64) against main, updates and security at the lock's snapshot 20260905T000000Z and at
20260926T000000Z.

- 33 have a newer version. At 20260905 itself, updates and security already carried
  util-linux 2.41.5-0+deb13u1 and its libraries, libexpat1 2.8.3-1~deb13u1 and OpenSSL
  3.5.7-1~deb13u2, which the runtime lock missed because it resolves `trixie main` only.
- At 20260926 **all 33 are in `trixie main`**: a point release (base-files 13.8+deb13u7)
  folded them in, with libc6 2.41-12+deb13u4, libsqlite3-0 3.46.1-7+deb13u2, perl-base
  5.40.1-6+deb13u1, gzip 1.13-1+deb13u1, libaudit 4.0.2-2+deb13u1, libglib2.0-0t64
  2.84.4-3~deb13u5, alsa 1.2.14-1+deb13u1, tzdata 2026c-0+deb13u1, and binNMUs of bash and
  e2fsprogs.
- The runtime rows have no resolver: `pin-inputs` rewrites inputs, build closures and the
  upstream closure, and leaves the runtime rows as imported on 2026-09-15.
- The release lock's `apt` row is one source, `trixie main` at the snapshot, which is what
  a consumer resolves an unpinned package from; resolving the runtime from the security
  archive as well would change that format (mica:docs/design/release-lock.md).

## Proposal

1. `pin-inputs` refreshes the runtime rows: every name the runtime lock pins is resolved
   again at the snapshot of `sources.json`, from `trixie main` as the `apt` row says, and the
   closure of those names is checked to be exactly those names (a version that pulls a new
   dependency is refused by name, for packages.tsv to take it). Tests on the pure part.
2. `sources.json` moves to 20260926T000000Z; `pin-inputs` rewrites the runtime, upstream and
   input rows. input.tzdata moves to 2026c: mica-tzdata becomes 2026c-mica1.
3. Build, gate, bootstrap the floor on amd64, `bun run check`; release, verified from the
   published artefacts.

## Risks

- A snapshot move changes the `apt` row consumers resolve from: mica-build's own resolutions
  from it move with it.
- Between point releases the gap reopens: security fixes land in `trixie-security` first.
  Closing it for good is the format change above, recorded in the task, not done here.

## Scope

src/pin-inputs.ts and src/container.ts, tests, sources.json, locks/upstream.lock,
packages.tsv if a closure moves, debs/mica-tzdata, docs.

## Alternatives

- Resolve the runtime from main, updates and security at 20260905: current too, but the
  `apt` row would no longer describe where the root came from.
- Hand-edit the 33 rows: no check that a new version's dependencies are pinned.
