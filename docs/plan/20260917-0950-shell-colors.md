# 20260917-0950-shell-colors Colored interactive shell profile

- **status**: implementing
- **createdAt**: 2026-09-17 09:50
- **approvedAt**: 2026-09-17 10:27
- **relatedTask**: 20260917-0950-shell-colors

## Context

- The product root (mica-build `rootfs/runtime/consumers.json`) dropped
  `/etc/profile`: base-files writes it from its postinst, so the package-owned
  rule never matched. Without it a login bash never sources `/etc/bash.bashrc`
  and shows `-bash-5.2#`. Fixed in mica-build as a `generated` rule (uncommitted).
- `/etc/profile` sources `/etc/profile.d/*.sh`; the product root has no
  `/etc/profile.d` today (systemd's `70-systemd-shell-extra.sh` is an unowned
  link and is dropped too).
- Retained tools: coreutils (`ls`, `dircolors`), grep, diffutils, ncurses-bin.
- root's `~/.bashrc` (base-files) sets nothing; mica's `~/.bashrc` (skel) sets
  its own prompt after `/etc/profile`, colored for `*-256color` TERMs.
- mica-system is version-locked: a payload change needs a `Version` bump in
  `debs/mica-system/control` and a Base release, then mica-build re-pins Base.

## Proposal

1. mica-system-base `payload/etc/profile.d/mica-shell.sh`:

   ```sh
   # Interactive bash on a color terminal: colored prompt, ls/grep/diff colors.
   [ -n "${BASH_VERSION-}" ] && [ -n "${PS1-}" ] || return 0
   case "${TERM-}" in xterm*|screen*|tmux*|rxvt*|linux|*color*) ;; *) return 0 ;; esac
   if [ "$(id -u)" -eq 0 ]; then _c='1;31'; else _c='1;32'; fi
   PS1="\[\e[${_c}m\]\u@\h\[\e[0m\]:\[\e[1;34m\]\w\[\e[0m\]\\$ "
   unset _c
   eval "$(dircolors -b)"
   alias ls='ls --color=auto' grep='grep --color=auto' diff='diff --color=auto'
   ```

2. `debs/mica-system/control`: `Version` 1.0.0-1 -> 1.0.1-1.
3. `tests/payload/shell.test.ts`: bash with a color TERM gets the colored PS1,
   `LS_COLORS` and aliases; `TERM=dumb` and non-interactive bash keep PS1; dash
   sources it with exit 0.
4. After the Base release, mica-build: re-pin Base, add `/etc/profile.d/*.sh` to
   the mica-system owned rule in `consumers.json`, and a composition test that
   keeps it; commit together with the `/etc/profile` fix.

## Risks

- Needs a Base release and a mica-build re-pin before it reaches a device.
- `checks-busybox.ts` reads `/etc/profile.d` for PATH edits; the script touches
  no PATH.
- Non-login interactive shells (`bash` typed at a prompt) read only
  `/etc/bash.bashrc` and `~/.bashrc`, so they inherit exported `LS_COLORS` but
  not the aliases or PS1.

## Scope

mica-system-base: 1 payload file, control, 1 test, docs. mica-build: lock/pin,
consumers.json, 1 test.

## Alternatives

- Seed root's `~/.bashrc` from a mica-owned file: covers non-login shells too,
  but only on first boot (existing `/mica/root` is left untouched).
- Ship nothing extra and only keep `/etc/profile`: restores `root@mica:~#`
  without colors.
